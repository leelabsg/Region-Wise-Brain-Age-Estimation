Allele convention check -- LDSC branch
======================================

Why this file exists
--------------------
The released 04_ldsc code does not carry the allele labelling that produced the
summary statistics behind ST14 and ST15. The earlier runs passed
`--a1 Allele1 --a2 Allele2` to munge_sumstats.py, which puts SAIGE's NON-effect
allele in the column LDSC reads as the effect allele. The released code passes
`--a1 Allele2 --a2 Allele1`, and 01_preprocess.py writes the matching
merge-alleles list. This file is the measurement behind the README's statement
that the correction changes no reported number.

The comparison was run at two scales against the same N = 41,067 input set:
in detail on chromosome 22 of the whole-brain (global) BAG GWAS, which is the
worked example below, and then across all 220 region-chromosome files. In both
passes the old-convention side was READ from the existing munged files; nothing
under the LDSC work tree was regenerated or modified.

A1 and Z against the source
---------------------------
Every munged SNP was matched back to the source row carrying the same unordered
allele pair, so multi-allelic markers resolve unambiguously. 105,260 of 105,260
resolved in both files; 0 unresolved.

  A1 == source Allele2 (effect allele)   0 / 105,260        105,260 / 105,260
                                         0.00 %             100.00 %
  Z == source BETA/SE (tol 6e-4)         105,260 / 105,260  105,260 / 105,260
                                         100.00 %           100.00 %
  sign(Z) == sign(source BETA)           105,227 / 105,227  105,227 / 105,227
    (excluding 33 SNPs whose Z rounds
     to 0.000 in the munged file)        100.00 %           100.00 %

So the correction moves the A1 label onto the effect allele and leaves Z alone.
That is expected from the LDSC source: munge_sumstats.py's allele_merge only
drops SNPs that fail to match --merge-alleles, it has no sign-flip branch.

rs429358 (APOE), worked through by hand
---------------------------------------
rs429358 is on chromosome 19, so it is NOT in the chr22 artefacts above. It is
worked out here from the final whole-brain GWAS (N = 41,067) and its munged
LDSC input, both read only.

  SAIGE output (whole brain, chr19)
    CHR 19  POS 45411941  MarkerID rs429358
    Allele1 C   Allele2 T   AF_Allele2 0.848991
    BETA -0.0515221   SE 0.00980716   p.value 1.492176E-07   BETA/SE = -5.2535

  munged sumstats (pad_global.sumstats.gz, --a1 Allele2 --a2 Allele1)
    SNP rs429358   A1 T   A2 C   Z -5.254   N 41067.0

  Z equals BETA/SE to the printed precision and A1 holds the effect allele T:
  beta(T) < 0, equivalently beta(C) > 0, i.e. the APOE e4 allele C raises the
  brain-age gap.


All 220 region-chromosome files
-------------------------------
The chr22 comparison was extended to the whole N = 41,067 LDSC input set: 10
regions x 22 autosomes. Each region's per-chromosome files were re-munged with
the released 02_munge.sh (--a1 Allele2 --a2 Allele1, --N 41067) into a separate
scratch work tree.

The new-convention merge-alleles lists were rebuilt from the same
per-chromosome sumstats the old run consumed. Before any of them was written,
the same generator was run under the OLD convention and required to reproduce
all 220 existing snplists byte for byte; that gate passed 220/220, which is
what licenses treating the flipped lists as 01_preprocess.py's own output.

  files compared                          220 / 220
  SNP set identical (old vs new)          220 / 220
  max |Z_new - Z_old| across all files    0
  A1 == source Allele2                    72,963,690 / 72,963,690   (100.00 %)

The SNP-set test compares every row, merge-allele placeholders included, so the
row counts agree per file as well as in total. The A1 test matches each munged
row to the source row carrying the same unordered allele pair, so multi-allelic
markers resolve unambiguously; 0 rows were left unresolved in any file. The
max |dZ| figure is an exact 0, not a tolerance: the Z column is bit-identical
in all 220 files, over the same 72,963,690 SNPs.

The per-file table -- SNP counts, max |dZ| and the A1 tallies for each of the
220 region-chromosome pairs -- was written as compare_220.tsv next to the
re-munged files. It is held on the analysis server and is not part of this
repository.


What this does and does not establish
-------------------------------------
Measured: across all 220 region-chromosome files of the N = 41,067 input set,
the correction leaves the SNP set unchanged and the Z column bit-identical
while moving the A1 label onto the effect allele for 100.00 % of rows. On chr22
of the global GWAS, where --h2 was run under both conventions, every h2
statistic is unchanged to the printed precision.

h2 and rg were not recomputed for the remaining files, and do not need to be:
LDSC reads only SNP, Z and N from a munged file, and all three are identical
here, so its output is unchanged by definition.

Not measured here: the two external traits, telomere length PC1 and
ProtAge-204. Both are munged by this same 02_munge.sh and carry the same
labelling, but neither was included in the 220-file sweep.

The summary statistics deposited with the paper were produced under the old
convention and have been left exactly as they were.


How to re-run this check
------------------------
Needs config/paths.env (GWAS_UKB_DIR, LDSC_DIR, LDSC_PYTHON, LDSC_WORK_DIR,
LDSC_REF_LD_CHR, LDSC_W_LD_CHR). Pick a scratch directory outside this
repository and outside $LDSC_WORK_DIR; nothing below writes to either.

  set -a; . gwas/config/paths.env; set +a
  WORK=<scratch directory>
  mkdir -p "$WORK/new/files/global" "$WORK/new/sumstats" "$WORK/old/sumstats"

  # 1. chr22 of the source sumstats
  awk -F'\t' 'NR==1{print;next} $1+0==22{print}' \
      "$GWAS_UKB_DIR/global/results/global_imputed_sumstats.txt" \
      > "$WORK/chr22_raw_global.txt"

  # 2. per-chromosome split + snplist, new convention
  "$LDSC_PYTHON" gwas/04_ldsc/01_preprocess.py \
      --save_path         "$WORK/new/files/global" \
      --save_file_name    global \
      --gwas_results_path "$WORK/chr22_raw_global.txt"

  # 3. munge. Write a copy of paths.env whose LDSC_WORK_DIR is "$WORK/new" and
  #    point GWAS_CONFIG at it. 02_munge.sh loops over all 22 chromosomes; only
  #    chr22 has an input here, so the other 21 jobs exit with an error and are
  #    expected to.
  GWAS_CONFIG="$WORK/new.env" bash gwas/04_ldsc/02_munge.sh global 41067

  # 4. the old-convention file is read, never rebuilt
  cp "$LDSC_WORK_DIR/munge_output/global/global_chr22_munge.sumstats.gz" \
     "$WORK/old/sumstats/pad_global_chr22.sumstats.gz"
  cp "$WORK/new/munge_output/global/global_chr22_munge.sumstats.gz" \
     "$WORK/new/sumstats/pad_global_chr22.sumstats.gz"

  # 5. heritability on each, with GWAS_CONFIG pointing at "$WORK/old" then
  #    "$WORK/new"
  GWAS_CONFIG="$WORK/old.env" bash gwas/04_ldsc/05_heritability.sh pad_global_chr22
  GWAS_CONFIG="$WORK/new.env" bash gwas/04_ldsc/05_heritability.sh pad_global_chr22

  # 6. column comparison
  diff <(zcat "$WORK/old/sumstats/pad_global_chr22.sumstats.gz" | cut -f1,4,5) \
       <(zcat "$WORK/new/sumstats/pad_global_chr22.sumstats.gz" | cut -f1,4,5)

03_merge_munged.py is not needed: one chromosome is enough for this comparison.

The 220-file sweep is the same steps 2-4 run for each region in turn over all
22 chromosomes, with the snplist gate of the previous section applied before
step 2. Step 5 is not part of it -- see "What this does and does not
establish" for why h2 was not recomputed.
